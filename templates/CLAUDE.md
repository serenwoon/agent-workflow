## 2. 근거 규율

### 근거 사다리 — 위에서부터. 건너뛰지 않는다

| 순위 | 어디 | 무엇의 근거인가 |
|---|---|---|
| 1 | **원본 문서** (`10_원자료/`) | 이 일의 모든 사실 |
| 2 | **조직 공식 자료** | 내부 용어 · 방법론 · 실적 |
| 3 | 용어집 | 용어 판정 기준 |
| 4 | 일반 지식 노트 | 개념 · 제도 |
| 5 | 외부 검색 | **위 넷에 없을 때만.** `(외부 검색)` 표시 필수 |

1·2를 확인하지 않고 5로 내려가지 않는다. 내부 용어를 외부 검색으로 정의하면 그럴듯한 오답이 나오고, 그게 제일 위험하다. 모르면 검색하지 말고 묻는다. "이 용어, 원본이나 사내 자료에 정의가 있나요?" 한마디면 된다.

### 확신 표시

| 표기 | 언제 |
|---|---|
| (표기 없음) | 원문·공식 자료·법령으로 확인됨 |
| `[확인필요]` | 원문 대조 안 함. **단정 금지** |
| `(외부 검색)` | 5순위. 근거 층이 낮음을 명시 |
| `[추정]` | 내 판단. 사실처럼 쓰지 않음 |

### 인용은 구절을 옮겨 적는다

링크만 다는 것으로는 부족하다. 실존 문서를 링크하면서 그 문서가 뒷받침하지 않는 내용을 쓰는 일이 가능하고, 이건 파일명 기반 검사를 100% 통과한다.

```
나쁨:  이 항목은 기한 내 완료를 요구한다 (원문 링크)
좋음:  {ID} — "{원문 구절을 그대로 옮겨 적는다}"
```

### 정의는 한 곳에만 둔다

같은 숫자나 정의가 두 파일에 있으면 이미 사고 예비 상태다. 원천 한 곳, 나머지는 링크.

## 4. 금지사항 (Hard Rules)

1. 🔴 **내부 용어를 외부 검색으로 정의하지 않는다.** 원본과 공식 자료가 먼저다. 모르면 묻는다
2. **없는 실적·수치를 지어내지 않는다.** 근거 없으면 `[확인필요]`
3. **같은 정의·수치를 두 파일에 복사하지 않는다**
4. **`10_원자료/`는 읽기 전용.** 편집·이동·삭제 금지
5. **기계 추출물을 "원문"이라 부르지 않는다.** 구절 대조를 거친 뒤에만
6. {프로젝트 고유 금지 — 섞이면 안 되는 두 대상, 쓰면 안 되는 톤 등}

## 5. 작업 프로토콜

1. `CLAUDE.md` → MOC → 미결 목록 순으로 읽는다
2. 🔴 **사실·용어·수치를 말하기 전에 2절 사다리를 탄다**
3. 항목을 인용할 땐 요약 색인이 아니라 **원문의 세부내용**을 확인한다
4. 작업 시작 전 "지금 무엇을 할지" 1~3줄로 선언한다
5. 🔴 **모르는 용어는 검색하지 말고 먼저 묻는다**
6. 사람에게 하는 확인 질문은 **응답당 최대 1개**

### 검증자 투입 시점 — 요청을 기다리지 않고 내가 먼저 제안한다

| 발동 조건 | 왜 |
|---|---|
| 본문 집필을 시작할 때 (1회) | 체계를 세워두고 시작하는 편이 낫다 |
| 큰 단위 초고가 끝날 때마다 | 넘어가면 되돌리기 비용이 커진다 |
| 근거 ID·수치가 많이 들어간 직후 | **인용이 원문에서 미끄러지는 지점** |
| 제출 직전 1회 | 밖에서 보는 눈으로 한 번 |

검증자는 새 세션에서 원본만 들고 시작한다. 내가 쓴 정리 노트는 주지 않는다. 프롬프트는 `prompts/04_evidence-audit.md`에 있다.
